Deterministic component in Python 3.11+ to calculate the next actual execution time of a simplified cron expression, respecting an IANA timezone such as `America/New_York`. It relies solely on the standard library (`datetime`, `dataclasses`, `zoneinfo`, `unittest`).

This repository serves as a **rigorous evaluation suite (*eval*)** to audit AI models' ability to handle complex Daylight Saving Time transitions (DST Gap/Fold) and strict type validation.

---

## 1. The Technical Problem
Adding minutes or hours directly to local times is insufficient for schedules that cross daylight saving time changes. During a DST spring-forward (*Gap*), some civil hours do not exist; during the fall-back (*Fold*), some hours occur twice. A scheduler that attaches a timezone without validating the result can produce an invalid instant, miss an execution, or choose the wrong fold.

The evaluated module iterates through civil dates and resolves each candidate cron time via a round-trip between local time and UTC. The comparison for the next instant is performed strictly in UTC, capped at a 400-year Gregorian cycle to prevent infinite loops.

---

## 2. Deterministic DST Policy
- **Gap (non-existent local time):** shifts the time forward by the gap duration, preserving the position within the interval (e.g., 02:30 -> 03:30).
- **Fold (repeated local time):** considers both actual occurrences, returning the first one strictly greater than `now`.
- **`now` aware:** interpreted as an exact instant and converted to the target IANA zone.
- **`now` naive:** interpreted as local time, rejected with `ValueError` if ambiguous or non-existent.

---

## 3. Eval Structure
- `cron_dst.py`: Gold-standard reference implementation and unit test suite (`unittest`).
- `cron_schedule.py`: Implementation generated by the audited model (e.g., Claude) isolated for testing.
- `runner.py`: The unified test harness that runs the official suite against the target engine.
